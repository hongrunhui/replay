## 一句话现状

driver 注入 Replay.io 预编译 chromium 的所有进程不崩，能录 V8 telemetry 事件，但 **libc 拦截层（recv/send/time）实际没捕获到任何字节**——回放时 chromium 看到空页面。下一步要让 chromium 在 replay 模式真复现录制内容。

## 启动命令（已验证 chromium 不崩）

```bash
cd open-replay/browser
DYLIB=$(pwd)/driver/build/libopenreplay_browser.dylib
APP=~/.replay/runtimes/Replay-Chromium.app/Contents/MacOS/Chromium
SESSION="test-$(date +%s)"

# 录制
DYLD_INSERT_LIBRARIES="$DYLIB" OPENREPLAY_MODE=record OPENREPLAY_SESSION="$SESSION" \
  OPENREPLAY_DEBUG_LOG=/tmp/log "$APP" --no-sandbox \
  --user-data-dir=/tmp/u-$SESSION --no-first-run --no-default-browser-check \
  --headless --disable-gpu https://baidu.com &
PID=$!; sleep 12; kill -INT $PID; sleep 3; pkill -f Replay-Chromium

ls "$HOME/.openreplay/recordings/$SESSION/"
```

## 下次 session 第一件事

**路径选择（开发日志最新条目里详述了）**：

### 路 A — DYLD_INTERPOSE 失效诊断
1. 在 `intercept/net.cc` 的 `my_recv` 顶部加 `fprintf(stderr, "[DEBUG] my_recv called fd=%d\n", sockfd);`
2. 重新 record，看 stderr 有没有这行
3. 如果有但 .orec 没事件 → mode_/IsRecording 路径 bug
4. 如果没有 → DYLD_INTERPOSE 对 chromium 不生效，改用 fishhook

### 路 B —— **更可能成功，推荐先试**
**放弃 libc 拦截**，找 chromium 主动调的"录字节"API：
1. grep chromium/src 看 `V8RecordReplayBytes` 被哪些非 V8 模块调（特别是 net/、blink/loader/）
2. 那些是 chromium 主动告诉 driver "这是我刚收到的 HTTP 字节" 的入口
3. 接进 record_real.cc 的 V8RecordReplayBytes 真实实现（已经实现 - 检查它是不是真录到这些 why）
4. 也看 `V8RecordReplayOnNetworkStreamData` 是不是带 buffer，目前我们只录 (offset, length, bookmark) 不录字节

## 关键决策回顾（不要问、不要重做）

1. ❌ 不再尝试自建 chromium 源码（B3 弃，太多组件 API drift）—— 用 Replay.io 预编译版
2. ❌ 不要扩展 driver 实现完整 113 符号 —— 现有 99 已经覆盖核心，剩下 14 也不影响"看到回放"
3. ✅ 全程基于 `~/.replay/runtimes/Replay-Chromium.app`（adhoc-signed，DYLD_* 穿透）
4. ✅ macOS arm64 only；Linux 不做
5. ✅ 全部 record/replay 路径用 atomic 指针守卫，不调 DriverState::Get() 防 lazy-init 递归
6. ✅ chromium 端有 16 处 fork bug 修补，全在 `patches/chromium/all-build-fixes.patch`（自建用，不影响预编译）
